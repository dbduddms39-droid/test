# 일단확인 (MVP)

구직자가 채용공고, 오퍼·합격 안내(문자·이메일 포함), 근로계약서에 적힌 근로조건을 **점검 기준 v2.2**(10개 주제, 32개 세부기준)에 따라 확인하는 웹앱입니다.
문서의 **기재 상태**와 **원문 근거**만 보여 주며, 법률 위반 여부·법적 효력·기업 신뢰도·향후 조건 변경 가능성은 판단하지 않습니다.
판정 기준의 단일 원천은 동결 기준표 `design-handoff/spec/04_점검기준표_v2.2_동결원문.md`입니다.

## 실행 방법

Node.js 20 이상이 필요합니다. AI 분석은 **Google Gemini API 무료 등급**(`gemini-3.5-flash-lite`)을 사용하며, 유료 모델로 자동 전환하지 않습니다.

```bash
npm install
# GEMINI_API_KEY 는 서버 환경변수로만 등록합니다 (코드·채팅·브라우저에 넣지 않음).
npm start                 # 실제 AI 분석, http://localhost:3000
npm run demo              # DEMO_MODE=true — 키워드 규칙 데모 (AI 아님)
```

- 키 발급: Google AI Studio(https://aistudio.google.com/apikey)에서 **결제 수단을 연결하지 않은 프로젝트**로 발급하면 무료 등급으로만 동작합니다. 결제(billing)를 켜면 유료 요금이 적용될 수 있으니 켜지 마세요.
- `GEMINI_API_KEY`가 없으면 데모로 바뀌지 않고, 분석 요청에 "AI 분석이 아직 설정되지 않았어요" 오류를 안내합니다.
- 데모 모드는 `DEMO_MODE=true`를 명시했을 때만 켜집니다. 데모 결과는 헤더 배지와 결과 화면 안내로 AI 결과와 구분됩니다.
- 무료 사용량 한도(HTTP 429)에 도달하면 "AI 무료 사용량 한도에 도달했어요"를 안내합니다.

### 이미지·PDF 업로드

- 입력 화면에서 **캡처 이미지 최대 5장**(JPG·PNG·WebP) 또는 **PDF 1개**를 올릴 수 있습니다 (파일당 10MB, PDF 10쪽, 스캔된 쪽 5쪽까지). 여러 문서를 동시에 비교하는 기능은 없습니다.
- 여러 장의 이미지는 **같은 문서의 연속 캡처**로 봅니다. 미리보기·개별 삭제·순서 변경(위로/아래로) 후 '텍스트 추출'을 누르면 정한 순서대로 한국어·영어 글자를 인식해 하나의 편집 가능한 문서로 합칩니다. 일부 이미지가 실패하면 나머지는 합치고 실패한 장을 표시합니다.
- **파일은 브라우저 안에서만 처리하고 서버로 보내지 않습니다.** 일반 PDF는 pdf.js로 텍스트를 추출하고, 이미지와 스캔 PDF 쪽은 Tesseract.js로 OCR 합니다.
- OCR 전처리(`public/ocr-prep.js`): 작은 칸마다 바탕 밝기를 구해 바탕이 비슷한 영역별로 '흰 바탕 위 검은 글자'로 맞춥니다. 색 배너·버튼의 흰 글자, 다크 모드 화면, 일부만 어두운 배너, 회색 칩·표 머리글을 모두 같은 방식으로 처리합니다(이전에는 어두운 가로줄 전체만 반전해 중간 밝기 배너 글자를 놓치고, 일부만 어두운 배너는 줄 전체가 망가졌습니다). 글자 크기를 재서 작은 글자(저해상도·메신저로 받은 캡처)는 키우고, 표 테두리·버튼 외곽선 같은 긴 직선과 가장자리 잔상을 지우고, 흰 여백을 둡니다.
- 제한적 재인식: 인식 결과에서 신뢰도가 낮은 단어가 있는 줄만(이미지마다 최대 8줄) 전처리 이미지·원본 이미지·1.5배 확대 이미지에서 한 줄씩 다시 읽고, 더 확실한 결과(평균·최저 단어 신뢰도)를 고릅니다. 모든 후보는 같은 이미지에서 실제로 읽은 글자이며, 글자를 추측해 고치지 않습니다. 칸 사이 빈 곳·테두리에서 생긴 기호 조각('_', '|')과 신뢰도 낮은 괄호 조각만 지웁니다.
- 배치에 맞춘 줄 엮기(`public/ocr-layout.js`): 정리된 이미지에서 행(가로 빈 띠)과 칸(넓은 세로 빈 곳)을 찾아, 인식된 단어를 위치대로 칸에 넣고 '항목명 + 값의 첫 줄', 값의 나머지 줄 순서로 다시 엮습니다. 표의 아이콘 칸(한글이 없거나 아이콘 크기에 확신이 낮은 칸)은 빼고, 행 가운데의 아이콘은 새 항목의 시작으로 봐서 좌우 2열 목록(복리후생 등)을 한 줄에 하나씩 나눕니다. Tesseract가 두 줄짜리 값 가운데의 항목명을 위아래로 잘라 읽거나(예: '근무시간' → '근' + '=e') 아이콘과 붙여 읽는 문제가 있어, 칸이 여러 개인 행은 칸마다 따로 다시 읽고 전체 인식보다 확실하거나 칸을 더 많이 덮는 결과를 고릅니다(전체 OCR만 / 배치만 / 배치+칸별 OCR 비교는 [docs/ocr-accuracy-report.md](docs/ocr-accuracy-report.md)).
- 결과 평가: 이미지마다 신뢰도와 함께 '확인할 부분'(신뢰도가 낮거나 `2O27`·`202712.31`처럼 숫자 사이에 글자가 섞이거나 날짜·시간에 없는 형태의 숫자, 한글 문서에서 신뢰도 낮게 영문으로 읽힌 단어 예: '스낵바' → `Addl`)와 '일부만 읽힘'(이미지에서 찾은 글자 줄 수보다 읽힌 줄이 크게 적음)을 판단해, 이미지 목록과 안내 문구로 원본과 비교할 곳을 알려 줍니다. 값은 인식한 그대로 보여 주고 고치지 않습니다.
- 정확도 비교: `node scripts/ocr-bench.mjs` (가상 채용공고 이미지 17장 `test/fixtures/ocr-bench/`(생성: `scripts/make-ocr-bench-fixtures.mjs`)과 실제 서비스에서 오류가 난 오퍼 안내문 캡처 2장 `test/fixtures/ocr-real/`(이름은 [이름]으로 가려진 이미지, 정답은 원본을 보고 옮겨 적음)). 수정 전후 비교 결과는 [docs/ocr-accuracy-report.md](docs/ocr-accuracy-report.md)에 있습니다.
- 추출 결과는 **S-03 추출본 확인** 화면에 원본 미리보기와 함께 편집 가능한 텍스트로 보여 주고 **자동으로 분석하지 않습니다.** '내용 확인하고 분석하기'를 눌렀을 때 확인·수정한 텍스트만 분석 API로 전송됩니다. 결과·상세 화면에는 '추출·확인한 텍스트 기준'임을 표시합니다.
- 직접 입력한 텍스트와 파일에서 추출한 텍스트는 따로 보관합니다. 화면 이동·뒤로 가기·재시도 중에는 이 창의 메모리에 유지되고, 새로고침하거나 창을 닫으면 사라집니다.
- 형식 오류·인식 실패·일부 실패·바꾸기 취소 때 이미 입력한 내용과 이미지 목록은 그대로 둡니다.
- 라이브러리와 언어 데이터는 외부 CDN이 아니라 같은 사이트의 `public/vendor/`에서 제공합니다 (처음 업로드할 때만 내려받음: PDF 약 2MB, OCR 약 8.5MB). `public/vendor/`는 `npm run vendor`로 `node_modules`에서 복사해 커밋한 파일입니다. Vercel은 빌드 스크립트보다 먼저 `public/`을 정적 파일로 수집하므로 빌드 때 생성하지 않고 커밋해 둡니다.
- 한계: OCR은 사진 품질·글꼴·기울기에 따라 오타가 생깁니다. 신뢰도가 높은데도 틀리는 비슷한 글자(예: 'OO'→'00', '응'→'음', '금'→'급', '헤'→'해', '·'→'-', 'D-12'→'0-12')는 표시되지 않을 수 있습니다. 작은 글씨의 일부 단어는 크기를 바꿔도 Tesseract 한국어 모델이 읽지 못해(예: '스낵바', '필요한') '인식이 불확실한 부분'으로만 알려 줍니다. 심하게 흐린 부분은 읽지 못하며 S-03에서 '일부가 빠졌을 수 있어요'(추정)로 알리고, 확인 표시 전에는 분석하지 않습니다. 표 테두리가 '_' 같은 기호로 섞일 수 있고, 여러 단 배치는 줄 순서가 섞일 수 있습니다. 연속 캡처가 겹치면 겹친 줄이 두 번 들어가므로 직접 지워야 합니다. 처음 OCR 때 내려받는 데이터 때문에 느린 네트워크·저사양 휴대폰에서는 시간이 걸립니다. 암호가 걸린 PDF는 열지 않습니다.

### 담당자에게 질문 복사

- 상세 화면에서 상위 상태가 **일부 내용만 기재됨** 또는 **관련 내용 찾지 못함**인 주제에만 '담당자에게 이렇게 물어보세요' 영역을 보여 줍니다. 주요 내용 기재됨·분석 확인 불가 주제와 화면에서 숨긴 08에는 질문을 만들지 않습니다.
- 질문은 `public/questions.js`의 고정 템플릿(10개 주제 × 문서 유형 × 상태)으로 브라우저에서 만듭니다. **AI를 추가로 호출하지 않고**, 문서에 적힌 금액·날짜·조건이나 근거 원문을 질문에 넣지 않습니다.
- '질문 복사'를 누르면 클립보드에 복사하고 "질문을 복사했어요"를 안내합니다. 복사가 막힌 브라우저에서는 문장을 선택해 두고 직접 복사하도록 안내합니다.

### 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | (없음) | Gemini API 키. 서버에서만 읽음 |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | 사용할 모델 |
| `DEMO_MODE` | (꺼짐) | `true`일 때만 데모 분석기 사용 |
| `AI_TIMEOUT_MS` | `60000` | AI 호출 1회 제한 시간 |
| `RATE_LIMIT_PER_IP` / `RATE_LIMIT_WINDOW_MS` | `5` / `60000` | IP별 요청 제한 |
| `RATE_LIMIT_GLOBAL_PER_MINUTE` | `4` | 서버 전체 분당 분석 수 |
| `RATE_LIMIT_GLOBAL_PER_DAY` | `100` | 서버 전체 하루(UTC) 분석 수 |
| `TRUST_PROXY` | (꺼짐) | `true`면 `X-Forwarded-For`로 IP 판단 (프록시 뒤에서만) |
| `PORT` | `3000` | 포트 |

분석 1건은 검증 실패 시 AI를 최대 2번 호출합니다. 요청 제한 기본값은 무료 등급 한도의 절반 이하가 되도록 잡았지만, 무료 한도는 Google이 바꿀 수 있으므로 AI Studio에서 현재 한도를 확인한 뒤 조정하세요. 요청 제한은 메모리 기반이라 서버를 재시작하면 초기화됩니다.

## 테스트

```bash
npm test             # 단위·통합 테스트 (실제 AI 호출 없음)
npm run report       # 가상 문서 F01~F11을 데모 분석기(AI 아님)로 실행 → docs/test-report-demo.md
npm run eval:live    # 가상 문서 F01~F11을 실제 Gemini API로 실행 → docs/test-report-live.md (GEMINI_API_KEY 필요, 실제 API 호출)
npm run eval:live -- --samples=F02,F05   # 일부 문서만 실행 (무료 사용량 절약)
```

- 규칙 엔진 테스트(`test/rules.test.js`)는 F01~F11(`test/v22-fixtures.js`, 출처 `design-handoff/tests/`)과 R01~R29 짧은 예시로 **서버의 인용 검증·상태 규칙**이 기획상 기대 판정(오라클)과 같은지 확인합니다. 여기서 AI 응답은 사람이 작성한 '올바른 추출값'이므로, **실제 Gemini의 정확도는 검증하지 않습니다.** AI가 잘못 답한 경우(허위 인용, 주 5일을 휴일로 인용, 단위 없는 급여를 확인됨으로, 포괄 문구 인용 등)에 서버 규칙이 막는지도 따로 확인합니다.
- `eval:live` 보고서는 기획상 기대 판정과 실제 실행 결과를 나란히 적습니다. 일치율은 측정값이며 모델 정확도 검증 완료를 뜻하지 않습니다.
- 문서는 모두 가상 문서입니다. 무료 등급 API에는 실제 개인정보가 담긴 문서를 넣지 마세요.

### GitHub Actions에서 실제 Gemini 연결 테스트

`.github/workflows/gemini-live-test.yml` — 수동 실행 전용(실제 API 호출). 저장소 Secrets의 `GEMINI_API_KEY`로 가상 문서 F01~F11을 앱 기본 모델과 같은 `gemini-3.5-flash-lite`로 분석하고, 보고서(`gemini-live-report`)를 아티팩트로 올립니다.
실행: 저장소 **Actions** 탭 → 왼쪽 **Gemini live test** → **Run workflow** → (선택) `samples`에 `F02,F05`처럼 문서 키 입력 → **Run workflow**.

### 브라우저 사용자 흐름 확인 (E2E)

`.github/workflows/web-e2e.yml` — 수동 실행 전용. 러너에서 웹 서버를 띄우고 실제 브라우저로 S-01 → 문서 유형 선택 → 가상 채용공고 붙여넣기 → 분석 → 결과(9개 또는 10개 주제) → 세부기준·원문 근거 확인을 진행하고, 부정 표현이 있는 가상 오퍼를 한 번 더 분석해 질문 영역 표시·질문 복사(클립보드)를 확인합니다. 화면 이동·입력 보존 흐름(`scripts/e2e-flow.mjs`, 데모 서버)과 S-05·S-06 결과 화면(`scripts/e2e-result.mjs`, 가상 문서의 올바른 추출값을 쓰는 가짜 분석기로 원문 근거 연결·내부 코드 비노출·링크·08 표시 확인)도 함께 실행합니다. 두 검사는 API를 호출하지 않습니다. 브라우저로 전달된 응답·페이지·서버 로그에 API 키가 없는지도 검사하고, 화면 캡처를 `web-e2e-screenshots` 아티팩트로 올립니다.
로컬: `DEMO_MODE=true node scripts/e2e-browser.mjs` (키 없이 흐름만, 데모 결과)

업로드 흐름은 `scripts/e2e-upload.mjs`가 가상 문서 파일(`test/fixtures/upload/`, 생성: `scripts/make-upload-fixtures.mjs`)로 일반 PDF·한국어 이미지(PNG·WebP·사진형 JPG)·스캔 PDF·연속 캡처 3장 추출 정확도, 여러 장 미리보기·삭제·순서 변경, 일부 실패, 입력 내용 유지, S-03 확인·수정, 수정한 텍스트의 분석 전달, 오류 안내(암호화·쪽수 초과·형식 오류·손상·10MB 초과), 외부 전송 없음을 검사합니다. 워크플로 입력 `base_url`에 배포 주소를 넣으면 붙여넣기·질문 복사 흐름과 업로드 흐름을 배포된 사이트를 대상으로 검사합니다.
로컬: `DEMO_MODE=true node scripts/e2e-upload.mjs`

### Vercel 배포 (Hobby 무료 플랜)

- Vercel이 루트의 `server.js`를 감지해 Node 서버리스 함수(Node 22)로 실행하고, `public/` 파일은 정적 파일로도 제공합니다. `server.js`는 Vercel용으로 `(req, res)` 핸들러를 default export 합니다 (로컬 `node server.js` 실행 방식은 그대로).
- **`/`(메인 화면)는 함수가 처리합니다.** 빌드 결과에서 함수가 `functions/index.func`(경로 `/`)라서 정적 `index.html`보다 함수가 먼저 받습니다. 그래서 함수 번들에 `public/index.html`이 있어야 합니다. `vercel.json`은 함수 번들에서 **`public/vendor/**`(약 20MB)만** 제외합니다. `public/**` 전체를 제외하면 배포 사이트의 `/`가 `{"error":"not found"}`가 됩니다 (실제로 겪은 장애, `test/vendor.test.js`가 막음).
- `/app.js`, `/styles.css`, `/vendor/...` 같은 나머지 파일은 정적 파일로 제공됩니다.
- Vercel 프로젝트의 **Settings → Environment Variables**에 `GEMINI_API_KEY`를 등록합니다. `NEXT_PUBLIC_` 같은 접두사를 붙이지 않습니다. `DEMO_MODE`는 등록하지 않습니다.
- 요청 제한은 함수 인스턴스 메모리에 저장되므로 인스턴스마다 따로 세고, 인스턴스가 바뀌면 초기화됩니다. 무제한 호출을 완전히 막지 못하며, 최종 상한은 Gemini 무료 등급 한도(HTTP 429)입니다. 결제가 연결되지 않은 키라면 한도 초과 시 요금이 아니라 분석 불가로 끝납니다.
- Vercel에서는 `X-Forwarded-For`의 첫 IP로 사용자를 구분합니다 (`VERCEL=1`일 때 자동).

배포 점검:
- **Vercel build check** 워크플로: 배포 관련 파일이 바뀌어 푸시되면 공식 CLI로 `vercel build`(계정 불필요)를 실행하고 `scripts/check-vercel-output.mjs`로 `/`·정적 파일·API를 확인합니다.
- **Deploy smoke test** 워크플로: 수동 실행, `base_url`에 배포 주소를 넣으면 새로고침(`/`), 정적·vendor 파일, `/api/config`, `/api/analyze`(가상 문서 1건)를 확인합니다. 로컬: `node scripts/smoke-deployed.mjs https://배포주소`
- 점검에는 **공개 운영 도메인**(예: `https://프로젝트명.vercel.app`)을 쓰세요. 배포마다 생기는 개별 주소(`프로젝트-해시-계정.vercel.app`)는 Vercel Deployment Protection 때문에 로그인 페이지가 나와 점검이 실패합니다 (앱 오류 아님).

## 동작 요약 (점검 기준 v2.2)

1. 원문을 줄 단위로 나누고 번호를 붙입니다. 원문과 위치는 그대로 보존하며, 마침표가 없다는 이유로 줄을 합치지 않습니다. 100자를 넘는 한 줄만 문장 경계에서 나눕니다.
2. AI에는 번호가 붙은 텍스트를 보내고, 32개 세부기준마다 **표현 유형**(`specific`·`coarse`·`undecided`·`conflict`·`negated`·`absent`), **원문 인용**(줄 번호 + 그 줄의 구절 그대로), **원문 기재값**(`source_value`), 06-a의 기간 유형, 02-a의 계산 입력값만 받습니다. **상태는 AI가 정하지 않습니다.**
3. 서버가 인용을 검증합니다(없는 줄, 줄에 없는 구절, 근거 없는 판단, 한 개뿐인 상충, 허용되지 않은 세부기준의 부정 표현 등). 핵심(C) 근거가 하나라도 실패한 **상위 항목은 응답 전체를 보류하고 그 항목만 1회 재분석**합니다. 재분석도 실패하면 해당 핵심 세부기준과 상위 항목을 `분석 확인 불가`로 두고, 허위 구절은 보여 주지 않습니다. 추가(D)만 실패한 경우 **독립성이 입증될 때만** 그 D를 `분석 확인 불가`로 둡니다: 오류가 '구절이 그 줄에 없음'뿐이고, 그 줄이 핵심 근거 줄이 아니며, 그 줄의 내용과 AI가 주장한 구절 모두에 그 주제의 핵심 판단 표현(금액·시간·장소·수습 등)이 없어야 합니다. 하나라도 입증되지 않으면 주제 전체를 재분석합니다. 검증 실패를 `확인되지 않음`·`관련 내용 찾지 못함`으로 바꾸지 않습니다.
4. 서버 규칙(`src/rules.js`)이 세부 상태 6개와 상위 상태 4개를 정합니다. 06은 항상 표시하고, 08은 07-a에서 수습 적용이 확인될 때만 표시합니다(표시 항목 9개 또는 10개). 명시적 부정 분기(06 기간 정함 없음, 07 수습 없음, 10 연차 없음), 조건부 핵심(06-b·07-b·10-b), 중립 안내·적용 범위 안내, 07의 수습 중 급여 보류 안내는 동결 기준표 문구 그대로 씁니다.
5. 기준표의 고정 경계 규칙은 AI 판단보다 우선합니다: 단위 언급 없는 급여는 01-b 확인되지 않음, '주 5일'은 휴일 근거가 아님, '휴무'만으로 지정된 휴일을 추론하지 않음, 연차 외부 참조만이면 10-a 일부 확인, 특정 근로조건을 지칭하지 않는 포괄 문구는 근거에서 제외.
6. 원문 기재값과 계산값을 분리합니다. 02-a 계산값은 원문의 시각·휴게로 서버가 다시 계산해 맞을 때만 쓰고, 휴게가 원문에 없으면 계산하지 않습니다. 격주 근무처럼 주마다 다르면 주별 값을 평균 없이 보존합니다.
7. OCR 저신뢰 구간(`public/ocr-spans.js`): OCR이 불확실하다고 알린 글자의 위치를 S-03에서 추적합니다. **사용자가 그 구간을 직접 고쳤거나 '원본과 대조해 확인했어요'를 누른 곳만 해제**하고, '내용 확인하고 분석하기' 버튼으로는 해제하지 않습니다. 해제되지 않은 구간은 위치(문자 구간)만 분석 요청에 보내고, 서버는 그 구간과 겹치는 세부기준을 확정하지 않습니다(핵심이면 상위 `분석 확인 불가`). 추가(D) 근거에만 걸리거나 어떤 근거에도 인용되지 않은 구간은, 구간 주변 문맥(앞뒤 낱말 포함, 숫자처럼 읽힌 O·l 등은 숫자로 바꿔서도 확인)에 그 주제의 핵심 판단 표현(금액·시간·장소·수습 등, `src/core-pattern.js`)이 없을 때만 독립으로 보고 추가 기준에만 적용합니다. 핵심 표현이 보이면 그 주제의 핵심 세부기준을 확정하지 않습니다(`ocr_low_confidence_related`). 같은 줄에 있다는 것만으로는 영향이 있다고 보지 않습니다(F08). 붙여넣기·대량 수정으로 위치 대응이 불가능해지면 새로 들어온 글자 전체를 확인 필요 구간으로 두고, 사라진 저신뢰 글자는 텍스트에 다시 나타나면 그 위치도 확정하지 않습니다. OCR 정보 없이 오탈자처럼 보인다는 추측만으로는 만들지 않습니다. 위치를 특정할 수 없는 확인 필요 항목(추출 텍스트에서 찾지 못했거나 수정 중 위치를 잃었고, 지금 텍스트에 같은 글자가 없어 위치로 보낼 수 없는 것)은 어느 조건에 영향을 주는지 판단할 수 없으므로, 사용자가 원본과 대조해 확인하기 전에는 분석하지 않습니다(`unlocatedPending`).
8. 추출 문제(`public/extract-issues.js`, S-03 '분석 전에 확인할 추출 문제'): OCR 처리 정책의 세 상황을 구분합니다.
   - **특정 글자만 불확실**: 위 7번 (분석은 허용, 확인하지 않은 구간만 확정하지 않음).
   - **일부 누락 의심**: 이미지·스캔 PDF 쪽의 OCR 품질 추정(인식한 줄 수가 이미지의 글자 줄보다 적음, 평균 신뢰도 낮음)으로 판단합니다. 추정임을 밝히고 실제 누락을 확정된 사실로 쓰지 않습니다. 사용자가 '빠진 내용을 직접 보완했어요'(추출 텍스트를 실제로 고쳤을 때만 받음) 또는 '원본과 비교해 추출 범위를 확인했어요'를 눌러야 분석할 수 있고, 분석 버튼은 어떤 문제도 처리한 것으로 보지 않습니다.
   - **추출 실패**: 글자를 전혀 얻지 못한 이미지와 스캔 PDF 쪽(이전에는 빈 쪽으로 조용히 넘어갔음). **쪽마다 따로** 관리하며, 그대로는 분석할 수 없습니다. S-02에서 다시 추출하거나, 그 쪽 카드의 '직접 입력' 칸에 원본 내용을 입력한 뒤 '원본을 보고 직접 입력했어요'를 눌러야 그 쪽이 복구됩니다. 추출 텍스트의 다른 쪽을 고치거나 공백만 넣은 것으로는 복구되지 않고, 여러 쪽이 실패하면 각각 복구해야 합니다. 직접 입력한 내용은 분석할 때 그 쪽 자리(앞쪽 텍스트 끝, 사용자가 텍스트를 고치면 위치를 따라 옮김)에 넣고, OCR 저신뢰 구간 위치도 넣은 길이만큼 옮깁니다. 복구 전에는 분석하지 않으므로 읽지 못한 쪽의 조건이 `관련 내용 찾지 못함`으로 표시되지 않습니다.
   - **빈 쪽**: '글자를 찾지 못한' 쪽(`no_text_found`)이고 원본 미리보기가 있을 때만 '원본에서 빈 페이지임을 확인했어요'를 고를 수 있습니다. 확인한 쪽은 분석 텍스트에 아무것도 넣지 않고(빈 쪽 자체의 AI 분석·상태·결과 카드 없음) 나머지 쪽을 분석하며, 결과 안내에 제외한 쪽을 밝힙니다. 파일 손상·쪽 그리기 실패·미리보기 실패에는 이 선택지가 없습니다. 시스템이 OCR 실패를 빈 쪽으로 정하지 않습니다(사용자가 표시하기 전에는 항상 '처리 필요'). 문서 전체가 비면 기존처럼 S-02에서 막고, S-03에서 남은 텍스트를 모두 지운 경우도 빈 입력으로 막습니다.
   - '원래 내용으로'로 처음 추출한 내용으로 되돌리면 직접 입력·보완 표시는 다시 '처리 필요'가 됩니다. 결과 화면에는 직접 입력·보완한 부분을 밝히고, 그 텍스트가 원본 전체를 빠짐없이 옮겼다고 보장하지 않는다고 안내합니다.
   - 한계: 사용자의 확인·입력 표시가 실제 대조를 거쳤는지, 직접 입력한 내용이 그 쪽 전체인지는 확인할 수 없습니다. '일부 누락 의심'의 '직접 보완' 표시는 아직 추출 텍스트 전체 기준(처음 추출한 내용과 다른지)으로만 확인합니다.
9. 부정 표현은 세부기준별로 정합니다: 07 수습 없음·10 연차 없음은 기준표의 허용 분기(확인됨), 09 휴일 없음은 일부 확인, 02 휴게 없음(미결정 D04)과 08 수습 중 급여 미지급은 기준표에 규칙이 없어 **잠정** 일부 확인으로 표시합니다. 그 밖의 세부기준에서는 부정 표현을 받지 않고 재분석합니다.

## 개인정보

- 입력 화면에 "이름, 연락처, 주민등록번호 등 개인정보는 가리고 입력해 주세요." "입력한 문서 텍스트는 분석을 위해 서버와 AI 모델에 전달됩니다."를 표시합니다.
- 서버는 원문을 저장하지 않고, 로그에는 세부기준 ID·오류 코드·단위 개수만 남깁니다. 브라우저도 원문·결과를 저장소에 남기지 않습니다(새로고침하면 사라짐).
- 업로드한 파일은 서버로 전송하지 않고 브라우저 메모리에서만 처리합니다. Tesseract.js는 언어 데이터(문서 내용 아님)만 브라우저 저장소(IndexedDB)에 캐시합니다.
- 보관·삭제 기간에 대한 문구는 API 제공업체의 데이터 처리 정책을 확인한 뒤 확정해야 하므로, 현재 화면에는 넣지 않았습니다.
- Gemini API **무료 등급**은 유료 등급과 데이터 처리 조건이 다를 수 있습니다(제출 내용이 Google 서비스 개선에 쓰일 수 있음). Gemini API 추가 약관을 확인하기 전까지는 가상 문서로만 테스트하세요.
