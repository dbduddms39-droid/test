## 4. v2.3 후보 규칙 (이번 동결본에는 반영하지 않음)

1. `neutral_note`를 항목별 고정 규칙과 명시적 대상 조합으로 정의. **유급·위법 판단은 하지 않되**, `02-c 휴게 없음`에 이 안내를 띄울지 명시적으로 결정.
2. 격주·순환 일정 계산은 `cycle_weeks` 및 `weekly_hours_by_cycle` 같은 구조로 저장하고, 원문의 근무표·휴게를 근거로 연결. 평균은 선택 계산값으로만 표시하며 주별 값을 숨기지 않음. 주기 자체가 불명확하면 PARTIAL.
3. `01-e`의 '이체 방식은 입사 후 안내'에서 수단(계좌이체 등)과 구체적 방식(계좌·절차)을 분리. 불확정 표현의 대상별 판정 정의.
4. `10-b`에서 '차등 부여'만 기재된 경우 `PARTIAL`과 `UNCLEAR`의 선후 규칙을 확정. **실제 부여 일수를 확정된 사실로 표시하지 않음.**
5. `06-a` 기간제 유형이 독립적으로 확인되고 종료 시점만 미확정인 경우의 세부 상태 명시.
6. OCR 오류가 없는 `F11-X` 변형을 별도로 만들어, `10-b`의 근속 구간/추후 안내 판단만 분리 검증.

## 5. Gemini 평가 시 주의할 점

- **현재 미실행:** 이 환경에는 `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`가 설정되어 있지 않음. 기존 GitHub 프로젝트의 라이브 평가 도구는 현재 구현 기준인 **8개 항목용**이므로, 동결된 10개 기준표의 실행 검증으로 간주할 수 없음.
- 모델 평가에는 동결 기준표와 가상 원문 F09~F11, 메타데이터만 입력하고 오라클 및 이 대조 보고서는 입력하지 않음.
- 실제 사용자 대상 UT가 아닌 **기준 해석 일반화 검증**이며, 같은 기준표로 모델이 내놓는 결과의 일관성과 오류를 분석하는 실험임.
- 새 세션에서 모델 판정이 출력되면 원문·세부기준·상위 상태·노트 발동 여부를 보존하고 **그 후에만** 기대/블라인드/모델의 3자 대조를 진행.
- 불일치 분류 5종: **기준 모호함 / AI 추출·해석 오류 / 원문 검증 실패 / OCR 신뢰도 문제 / 기대 판정 오류.** 한 건에 여러 요인이 있으면 주원인과 부원인을 구분.
