## 1. 배경과 문제 근거

### 1-1. 탐색 설문

- 조사: `채용공고와 실제 근로조건 경험 조사_응답`, 2026.10.06~10.08, 전체 29건. 입사지원 경험자 27명을 관련 질문의 분모로 사용.
- 공고와 다른 조건을 안내받은 경험: **12/27명**. 그중 최종합격 안내·계약서 작성·출근 후에 차이를 알았다는 응답 **6/12명**.
- 공고 저장 경험: **24/27명**; 마감·수정·삭제로 이전 공고 재확인 어려움 **15/27명**.
- 이전 공고와 이후 안내/계약서의 주요 또는 일부 조건을 비교한 응답 **16/27명**; 그중 문서를 번갈아 보며 직접 비교한 응답 **8/16명**.

**해석 한계:** 편의표본이고, 이 수치는 **'법정 기준 기반 점검을 별도 서비스로 이용하겠다'는 수요나 일단확인의 효과를 증명하지 않는다**. 기존 설문은 근로조건 확인·재확인 행동의 맥락 근거다. 직접 사용자 UT는 아직 실시하지 않았으며, 새로운 참가자 모집을 필수 선행조건으로 삼지 않는다.

### 1-2. 외부 자료와 제품 역할

- [근로기준법 제17조](https://www.law.go.kr/법령/근로기준법/제17조), [시행령 제8조](https://www.law.go.kr/법령/근로기준법시행령/제8조), [기간제법 제17조](https://www.law.go.kr/법령/기간제및단시간근로자보호등에관한법률/제17조): 근로조건을 항목별로 확인할 공식적인 출발점을 제공.
- [고용노동부 2025년 개정 표준근로계약서](https://www.moel.go.kr/info/etc/dataroom/view.do?bbs_seq=20250300356): 공식 서식의 항목 구성을 참고.
- 출처는 기준 **설계 근거**이지, 서비스의 법률 자문 자격이나 개별 계약의 적법성 인증이 아님.

### 1-3. 해결 문제의 경계

> 구직자가 **지금 받은 문서 한 건**에서 확인해야 할 근로조건의 큰 항목과 세부 내용을 체계적으로 살펴보고, 적혀 있는 사실과 아직 문서에서 확인할 수 없는 사항을 구분한다.

과거 공고 보관과 두 문서 간 조건 변화 비교는 기존 설문에 드러난 별도 문제지만, **이번 버전의 해결 범위가 아니다**.

## 2. 제품 목표와 비목표

**목표**

1. AI가 문서의 조건 후보를 추출하고, **고정된 핵심(C)·추가(D) 기준**으로 정리한다.
2. 10개 주제를 점검하되 **08 수습 중 급여는 실제 수습 적용이 문서로 확인된 경우에만 노출**한다.
3. 상위 4개, 세부 6개 상태에 대해 일관된 라벨과 검증 가능한 원문을 제공한다.
4. 세부 기준마다 출처 유형 `L-M/L-W/F/S`와 참고 출처를 구분해 보여준다.
5. OCR·AI·근거 검증 실패를 '내용 누락'으로 바꾸지 않고, 사용자 수정·재시도 경로를 제공한다.

**비목표**

- 조건이 합법·불법인지, 사용자가 수락해야 하는지, 실제로 회사가 어떤 조건을 적용할지 결정하지 않는다.
- 사용자 대신 회사에 연락하는 것을 핵심 흐름으로 삼지 않는다.
- 두 문서 간 차이 자동 검출, 채용 건별 아카이브, 계정 기반 알림은 이번 범위 밖이다.
- ChatGPT나 다른 점검 서비스보다 정확·편리하다고 **증명되지 않은 우월성을 주장하지 않는다**.

## 5. 점검 대상·판정 정책

### 5-1. 10개 점검 주제

| 번호 | 항목 | 핵심(C) 예시 | 추가(D) 예시 |
|---|---|---|---|
| 01 | 임금 | 금액/산정값 + 산정 단위 | 구성·계산·지급방법, 지급일, 세전/세후 |
| 02 | 근무시간 | 소정근로시간 | 출퇴근 시각, 휴게, 근로일·일별 시간 |
| 03 | 근무장소 | 식별 가능한 취업 장소 | 재택·파견, 변경 조건 |
| 04 | 담당업무 | 실제 수행할 업무 | 추가 업무 범위 |
| 05 | 고용형태 | 확정된 계약 형태 | 전환 조건 |
| 06 | 계약기간 | 기간 정함 여부 + 기간제일 때 범위 | 갱신 기준 |
| 07 | 수습기간 | 적용 여부 + 적용 시 기간 | 평가·전환 기준 |
| 08 | 수습 중 급여 | 금액·비율 또는 확정 가능한 참조 | 종료 후 임금 |
| 09 | 휴일 | 지정된 휴일의 요일·주기·일정 | 유급 여부, 추가 휴일 |
| 10 | 연차 유급휴가 | 부여 여부 + 부여 시 문서가 언급한 구간의 기준 | 사용·신청 방식 |

**08 표시 의존성:** 07-a가 '수습 적용'으로 확인된 경우만 표시한다. '수습 없음', '미정', 수습 관련 원문 없음은 **08 미표시**이며 상위 상태도 만들지 않는다. 이때 07 상세에 미표시 사유를 안내한다. 현 동결 기준에서는 06을 포함한 나머지 9개 주제는 항상 점검·표시하며, 실표시 주제 수는 9개 또는 10개이다. 계약기간 정책 변경은 D02로 관리한다.

### 5-2. 상위 상태 4종

| 코드 | 사용자 라벨 | 의미 |
|---|---|---|
| `MAIN_FOUND` | 주요 내용 기재됨 | 항목별 핵심(C)이 구체적이거나, 제한된 명시적 부정 분기가 직접 확인됨 |
| `MAIN_PARTIAL` | 일부 내용만 기재됨 | 관련 원문은 있지만 핵심(C)이 누락·미확정·상충 |
| `MAIN_MISSING` | 관련 내용 찾지 못함 | 관련 원문 없음. 법적 의무 누락 판단 아님 |
| `MAIN_UNAVAILABLE` | 분석 확인 불가 | OCR/AI/근거 검증 문제로 핵심 판정 불가 |

### 5-3. 세부 상태 6종

`CONFIRMED(확인됨)` / `PARTIAL(일부 확인)` / `UNCLEAR(불분명함)` / `MISSING(확인되지 않음)` / `NOT_APPLICABLE(해당 없음)` / `UNAVAILABLE(분석 확인 불가)`.

- 상위 상태는 **C**로 결정한다. 추가 **D**가 빠졌다고 상위를 낮추지 않는다.
- **06 기간 정함 없음, 07 수습 없음, 10 연차 미부여**는 명시적 부정 분기. 09 '휴일 없음'은 09-a `PARTIAL`, 상위 `MAIN_PARTIAL`이며 부정 문구가 있다는 이유로 '휴일 지정'을 확정하지 않는다.
- **정보 상태는 긍정/부정 평가가 아니다.** 초록 합격, 빨간 위험 배지, 법률 준수 점수를 금지한다. '연차 미부여'는 내용 그대로 표시하며 효력은 판단하지 않는다.
- '기타 사항 별도 안내' 등 **대상을 특정하지 않는 포괄 문구는 모든 항목의 근거에서 제외**.
- 문서에 읽힌 내용 자체가 부족하면 `PARTIAL`; **시스템이 핵심값을 안전하게 읽지 못한 경우**에는 `UNAVAILABLE`.

### 5-4. 출처 코드·법률 적용

- `L-M`: 법령 명시 주제 / `L-W`: 법령 서면명시·교부 주제 / `F`: 공식 서식 참고 / `S`: 서비스 추가 구체성 기준.
- 각 세부기준에 코드와 실제 링크를 제공. **법률 적용 여부를 자동 확정하지 않는다**.
- 5인 미만 사업장, 주 15시간 미만 근로자처럼 실제 적용 요건이 필요한 경우에도 숫자만 감지해 항목을 `NOT_APPLICABLE`로 바꾸지 않는다.
- `neutral_note`: 근로조건의 지급·부여·적용 자체를 명시적으로 부정한 표현에 조건부 표시.
- `applicability_note`: 휴일·연차 자체의 미부여·미적용 표현에 한해 고정 안내. **휴게 부정문은 기준상 경계가 남아 있어 채점 보류**.

디자인 확장 여지(P1): 근로계약서 S-05 결과 목록 하단에는 향후 별도 추가 섹션을 삽입할 수 있도록 레이아웃만 고려한다. **P0 화면에 준비 중·미구현 기능 문구나 빈 카드 등은 노출하지 않는다.** 추가 항목·미분류 조항·집계는 P0 화면에 미포함.

기본 정보 계층: **문서에 적힌 문구 → 세부 기준별 확인 범위 → 기준 출처**. 기재 상태만 보고 법적 평가로 오인하지 않도록 라벨과 색은 항상 중립적으로 설계한다.

## 7. 품질·개인정보·접근성

- 인용 원문은 사용자 확인 완료 텍스트에서 **정확하게 재현**하며, 인용 실패 시 해당 항목 1회 재분석 후 실패 상태로 처리한다. 검증되지 않은 문구를 원문처럼 보여주지 않는다.
- 산술로 얻은 시간·기간 등은 **'원문 기재값'과 '계산값'을 분리**해 표시한다. 근거 없는 계산 금지.
- 저신뢰 OCR이 핵심(C)에 걸리면 상위 U. 추가(D)만 불확실하고 C가 독립적으로 검증되면 추가 U·상위 유지.
- 업로드 파일의 실제 처리 방식·외부 API에 전달되는 텍스트 범위·보존 정책과 개인정보 안내가 일치해야 한다. 현행은 파일 OCR을 브라우저에서 처리하고 **사용자가 확인한 텍스트는 분석 서버/모델 호출에 사용**한다. '문서 내용이 서버로 전송되지 않는다'라고 통칭해서는 안 된다.
- 숫자만 감지해 실제 법률 적용 제외를 주장하지 않는다. 출처 링크는 법령·표준서식·자체 기준을 구분한다.
- 색만으로 상태를 구분하지 않고 문자를 병기한다. 항목은 키보드로 이동·확인 가능해야 한다.

### 11-3. AI 역할, 원문 범위 및 표시 문구

1. **고정 설명 원칙:** AI는 조항·원문 후보를 추출하고 미리 정의된 영역에 분류한다. 사용자에게 노출하는 쉬운 설명은 **영역별 고정 템플릿**으로 시작한다. AI 자유 생성으로 법적 효력·무효·위험 가능성을 추정하지 않는다.
2. **④ 금전 부담 고정 안내 초안:** `근로자가 부담할 수 있는 금액이나 반환 조건이 적혀 있어요. 이 조항의 효력은 판단하지 않아요.` 금전 약정의 상세 효력 판단과 법률 조항 설명은 일반 결과 상태와 분리한다. 상담 안내 링크/표시는 추후 출처 확인 뒤 별도 검토한다.
3. **원문 조항 단위 분류:** P1-B에서 사용자가 확인한 텍스트를 줄/구간/조항 단위로 분리하고 기존 10개·추가 영역·미분류에 매핑하는 설계를 검토한다. 동일 구간이 여러 영역과 관련되면 다중 매핑을 허용하되 원문 커버리지 검사에서 중복으로 오인하지 않는 방식을 정의해야 한다.
4. **커버리지 경계:** 검증 가능한 범위는 `분석 대상으로 확보된 텍스트의 구간 매핑 누락 여부`다. **계약서 이미지의 모든 조항이 누락 없이 읽혔거나 의미적으로 전부 발견됐다는 보장은 하지 않는다.** OCR 누락·저신뢰 페이지/구간을 구분하고 사용자 재확인 경로를 제공한다.
5. **미분류 조항:** 확보된 텍스트에 매핑되지 않은 구간을 원문 그대로 보이는 방식은 P1-B의 검토 후보. `AI가 특이한 조항을 모두 찾아냈다`는 보장 표현 금지. 일반 인사말 등 계약조건이 아닌 문구의 분류 정책도 P1에서 별도 정의한다.
6. **빈 상태 문구 초안:** `이번 분석에서 별도로 발견된 추가 조항이 없습니다. 분석한 텍스트 기준이며, 계약서에 다른 조항이 없거나 법적으로 문제가 없다는 뜻은 아닙니다.` 발견형 영역에서만 사용하고 기재 확인형 ①·②의 미발견 상태를 이 문구로 대체하지 않는다.

### 11-4. P1 디자인·검증 진입 조건

- **지금:** S-05 근로계약서 결과 목록의 하단에 향후 확장 섹션이 붙을 수 있도록 배치 여지만 고려한다. 화면에는 `준비 중`, 보이지 않는 기능의 빈 카드, P1 추가 점검 수를 표시하지 않는다. S-01 메인화면 디자인과 별도 관리한다.
- **P1 시안 제작 시:** ④ 등의 조항 **2건 발견 화면**과 **0건 빈 상태 화면**을 동시에 제작하여 '안전한 계약서' 오해 여부를 검토한다. P1용 시안이라고 명확히 표기한다.
- **P1 구현 전:** 두 신규 기재 확인형 영역의 C/D, 출처 코드 및 판정 경계, 문서 유형별 표시/집계, 기존 `03-c/06-c/07-c` 중복 방지, 조항 원문 검증, OCR 누락 처리, 설명 템플릿·오라클을 확정한다. 법령 적용 범위 검토(D06)는 계속 미완료로 관리한다.
- **변경 관리:** 이 §11은 기존 D01~D06과 v2.2 동결 기준표의 판정을 수정하지 않으며 P1 새 기준은 **별도 후속 기준 문서/버전**으로 정의한다.
