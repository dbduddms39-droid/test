### 1-2. 코드·라벨 고정

**상위:** `MAIN_FOUND=주요 내용 기재됨`, `MAIN_PARTIAL=일부 내용만 기재됨`, `MAIN_MISSING=관련 내용 찾지 못함`, `MAIN_UNAVAILABLE=분석 확인 불가`.

**세부:** `CONFIRMED=확인됨`, `PARTIAL=일부 확인`, `UNCLEAR=불분명함`, `MISSING=확인되지 않음`, `NOT_APPLICABLE=해당 없음`, `UNAVAILABLE=분석 확인 불가`.

`—`는 상태가 아니라 **미표시**다. `neutral_note`와 `applicability_note`는 상태가 아니라 별도 안내 플래그다. 모든 상태는 정보 상태로 시각화하고 법적 승인/위험을 뜻하는 색·아이콘을 사용하지 않는다.

## 2. 입력과 화면별 기능

### F-01 [P0 유지] 문서 유형 선택
- **입력:** `job_posting | offer | labor_contract`.
- **처리:** 선택값을 화면·분석 요청·결과에 유지. 문서 유형에 따른 기준 출처 안내 문구를 선택.
- **AC:** 세 문서 모두 동일한 C/D 기재 상태 구조로 처리. 채용공고의 빈 항목을 위법으로 표현하지 않음. 누락 항목의 목록 노출은 D01 미결정.

### F-02 [P0 유지] 텍스트 입력
- **입력:** 사용자가 붙여넣거나 작성한 원문.
- **처리:** 빈 문자열·공백만 입력 차단. 사용자가 확인한 원문을 인용 검사 기준으로 사용.
- **AC:** 금액·시각·줄바꿈을 임의 치환하지 않음. 포괄 문구는 특정 항목의 증거로 확대 사용하지 않음.

### F-03 [P0 유지] 이미지/PDF 추출
- **입력:** 채용공고·오퍼·근로계약서 사진 또는 PDF.
- **처리:** 이미지·스캔 문서 OCR, 텍스트 PDF 텍스트 추출. 현행 파일 처리와 별개로 저신뢰 위치·원인 메타데이터를 **실제 구현 가능한 수준으로** 전달하는 설계가 필요.
- **AC:** 낮은 OCR 신뢰도가 핵심(C) 값에 영향을 주는지, 추가(D)에만 영향을 주는지를 구분할 근거 없는 경우 '정확한 구간별 신뢰도 판정 구현됨'이라고 표시하지 않는다. 추출본 수정·재분석 가능.

### F-04 [P0 유지] 사용자 텍스트 확인·수정
- **처리:** 추출한 텍스트를 사용자가 원본과 대조·수정 후 분석. 최종 수정 텍스트와 입력 방식(직접/텍스트 PDF/OCR)을 유지.
- **AC:** AI 요청·근거 검증·계산 모두 최종 확인 텍스트 기준. OCR 저신뢰 플래그가 수정된 위치에 계속 유효한지는 **원본/수정 구간 관리 정책**을 추가 설계해야 함.

### F-05 [차기 P0 신규] 10개 주제·세부기준 추출
- **입력:** 확인 완료 텍스트, 문서 유형, 적용 기준표 버전.
- **처리:** AI는 각 주제에 대응하는 원문 후보·줄 번호·값·표현 유형·미정/상충 사실을 구조화하여 반환. 서버는 반환값을 기준표에 대조해 세부 상태와 상위 상태 결정.
- **검사:** 후보 누락/중복, 근거 번호 불일치, 근거 없는 확정, 다른 항목 숫자 전용, 문서 내 상충 은폐, 포괄 문구 과잉 연결 금지.
- **AC:** 총 10개 주제를 식별하며 세부 ID는 변경 없이 출력. AI가 임의로 L/F/S 코드나 법적 판정 항목을 추가하지 못함.

### F-06 [차기 P0 신규] 상태 결정·노출 정책
- **처리 순서:** (1) 입력/원문 검증 상태 → (2) 항목 간 의존성 → (3) 세부 C/D 판정 → (4) 상위 상태 → (5) 표시·집계 → (6) 안내 플래그.
- **핵심 판정:** 검증 실패로 C 확정 불가면 U. 기준표가 허용한 명시적 부정 분기(06·07·10)는 조건에 따라 F로 판정하되, **06의 ‘기간 정함 없음’에는 `neutral_note`를 붙이지 않고 07 ‘수습 없음’·10 ‘연차 없음’의 부정 사실에는 안내를 붙인다.** 허용 목록 밖 부정(예: ‘휴일 없음’)은 해당 항목 규칙에 따라 판정하고 안내 플래그를 별도로 결정한다. C 모두 확정되고 상충 없으면 F. 관련 원문 있지만 부족·미정이면 P. 관련 원문 없으면 M.
- **AC:** 07-a 수습 적용 `CONFIRMED`일 때만 08 존재. `수습 여부 추후 결정, 적용 시 급여 90%`여도 08 미표시, 95% 등 문구는 07 상세에 사실만 설명할 수 있음. 분모는 표시된 9/10개(06 포함). 08 미표시를 M/F/U로 기록하지 않음. 채용공고 M은 접혀 있더라도 집계 포함(D01).

### F-07 [차기 P0 확장] 원문 근거 검증·1회 재분석
- **처리:** 입력 원문의 줄과 AI의 인용·번호를 직접 대조한다.
- **핵심(C) 근거:** 핵심값·조건부 분기·상충·부정 분기에 필요한 원문은 모두 필수 근거. 한 개라도 허위/불일치면 **해당 상위 항목 전체 보류**, 문제 항목만 1회 재분석. 성공하면 정상 결과, 다시 실패하면 해당 항목 U.
- **추가(D) 근거:** C의 완전성을 독립적으로 확인할 수 있는 경우 D만 U, 상위 보존. 근거 분리가 불확실하면 전체 재분석 우선.
- **AC:** 사용자에게 없는 인용 표시 0건. 허위 구절만 제거하고 남은 일부 근거로 상충 결과를 확정하지 않음.

### F-08 [차기 P0 신규] 계산값·원문값 분리
- **처리:** `source_value`, `derived_value`, `derivation`, `value_kind=quoted|calculated`, `evidence_ids` 구분.
- **허용:** 확정된 시각표·휴게·근로일 등에서 단순 산술이 가정 없이 가능할 때만 계산. **원문 검증은 인용 문자열·줄 번호에만**, 계산은 수식/입력값 일관성을 별도 검증.
- **금지:** 외부 법령 숫자 대입, 비어 있는 휴게시간 임의 가정, OCR 불확실 숫자 계산, 상충값 중 임의 선택.
- **미결정:** 격주 40h/43h를 순환 값 목록으로 표현할 데이터 구조. **평균 41.5h만 보여주거나 항상 40h로 단정 금지**(D03).

### F-09 [차기 P0 신규] 기준 출처 표시
- **기준 코드:** `L-M | L-W | F | S`. 출처 링크/설명은 서버 설정 또는 정적 기준표에서 제공하며 AI 자유 생성 금지.
- **문서별 안내:** 채용공고·오퍼는 참고 목록, 근로계약서는 관련 법령 근거라는 문장으로 안내하되 **어느 쪽도 적법성 판정 아님**을 고지.
- **AC:** 하나의 L 코드가 곧바로 해당 개별 세부기준의 독립적인 법적 의무인 것처럼 표현되지 않음. 정부 인증 마크·법률 위험 점수 없음.

### F-10 [차기 P0 신규] 조건부 안내
- `neutral_note`: 근로조건 **부여·지급·적용 자체를 명시적으로 부정**할 때 원문 사실 확인과 비법률판단 고정 문구 노출. 단순 근무 일정의 부정 표현 또는 '기간의 정함 없음'은 제외.
- `applicability_note`: 휴일·연차 자체의 미부여·미적용 문구가 있는 경우에만 법률 적용 범위 불확실성 고지. 상시 인원/주당 시간 숫자만으로는 자동 발동하지 않음.
- **미결정 D04:** '휴게시간을 두지 않음'이 `neutral_note` 대상인지. 현재 정확도 채점 제외, 최종 실행 규칙 수정 필요.
- **AC:** 상태값 자체를 법적 판단으로 쓰거나 `NOT_APPLICABLE`로 법률 적용 제외를 나타내지 않음.

### F-11 [차기 P0 확장] 원문 상세·확인되지 않은 내용
- 각 주제 상세: 상위 상태 + 문서 사실 요약 → 검증된 원문 근거 → C/D 세부 기준 목록/상태 → 출처 → 필요한 고정 안내 → '이 문서에서 확인되지 않은 내용'.
- '담당자에게 물어보세요' 문구/복사는 현재 구현에서 존재하지만 **보조 기능**으로 두며 결과 열람 또는 성공 여부의 필수 조건으로 삼지 않음.
- **AC:** 상위 F라도 D의 M·P·U를 숨기지 않음. 상충 시 양쪽 원문 노출. 07의 수습 적용이 불명확하면 08 미표시 사유 표시.

### F-12 [P0 유지·확장] 오류·재분석·입력 보존
- 오류: 입력 미완성, 파일 형식/암호/손상, OCR 저신뢰, AI 모델/API 실패, 근거 불일치 구분.
- **AC:** 분석 실패를 '관련 내용 찾지 못함'으로 대체하지 않음. 사용자의 원문 수정/재시도 가능. OCR 핵심 저신뢰는 `MAIN_UNAVAILABLE`, D만 저신뢰이면 해당 D `UNAVAILABLE`(독립 검증이 가능하다는 전제).

### F-13 [P0 유지] 개인정보·이벤트
- 원본 문서 파일은 현행 브라우저에서 추출 처리. **최종 확인 텍스트는 분석 API로 전송**하므로, 이를 포함한 정확한 데이터 흐름·삭제 정책을 안내.
- 분석 이벤트에 개인정보·원문·원문값을 남기지 않는다. 로그 정책은 실제 운영 코드로 검증.
- AC: 저장 기능이 없는데 '언제든 다시 찾을 수 있음' 주장 금지. 외부 모델 호출과 파일 로컬 처리의 차이를 설명.

### F-14 [제외] 두 문서 비교·장기 보관
- 이번 차기 P0에 포함하지 않는다. UI 버튼·홍보 문구에 구현 완료로 표현하지 않는다.

**주의:** 예시 객체는 '정책 개념' 설명용이고, 기존 API 응답 또는 구현 확정 스키마가 아님. 상위 숨김 주제 08은 일반적으로 `items`에서 제외하는 것을 권장하나, '숨김 사유'를 기록할 내부 정책은 기술 검토 후 결정. 세부 링크 ID는 정적 출처 맵에서 매핑.

## 8. 변경 이력

- **v1.0 → v2.0 기획 초안:** 8→10 주제, 기존 09/10 참고만 정책 폐지, 상위 4·세부 6 상태, C/D 기준·세부 ID, 08 조건부 노출, 9/10 집계, 출처 주석, 계산값/원문값 분리, 안내 플래그 독립화.
