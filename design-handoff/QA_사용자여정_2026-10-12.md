# 일단확인 — 결과 화면 1차 사용자 여정 QA (2026-10-12)

## 검증 범위
`test/user-journey-qa.test.js`에 가상 채용공고·오퍼·근로계약서 5개 여정 테스트를 추가했다. 테스트는 사람이 원문 구절과 값을 지정한 **모의 AI 응답**으로 `analyzeDocument → compareDocuments → buildCompareQuestions / buildContractQuestions`를 실행한다.
**실제 Gemini 추출, 실제 사용자 이해도, 브라우저 화면 레이아웃·클릭, OCR 정확도는 검증하지 않았다.**

## 실제 테스트 출력
| 상황 | 확인한 대표 결과 | 생성 질문 개수 |
| --- | --- | ---: |
| 구체적인 공고 → 연봉만 적힌 짧은 최종 오퍼 | 연봉 동일; 근무시간·장소·업무는 비교 불가 | 5 |
| 공고 급여 협의 예정 → 구체적인 최종 오퍼 | 급여 추가 질문 없음; 나머지 두 문서 모두 미기재 | 6 |
| 공고 급여 협의 예정 → 최종 오퍼도 협의 예정 | 급여 확정 시점/기준 질문 생성 | 7 |
| 최종 오퍼 연봉 3,600만원 → 계약서 연봉 3,200만원, 수습 3개월 및 급여 90% | 급여 달라짐; 수습기간 분석 확인 불가; 수습 급여 비교 불가 | 7 |
| 연봉만 적힌 계약서 단독 | 급여 지급방법·지급일 등 9개 주제 질문 | 9 |

## 확인한 긍정적 행동
- 금액 차이가 있을 때 원문에 적힌 서로 다른 금액을 그대로 인용해 확인 질문을 생성한다.
- 채용공고에서 협의하던 급여가 오퍼에서 확정된 경우 그 사유로 급여 질문을 하지 않는다.
- 최종 오퍼에도 급여가 협의 중인 경우 확정 시점과 기준을 묻는다.
- 단독 계약서에서 수습 급여는 수습 적용 근거가 없는 경우 숨긴다.
- 각 테스트에서 비교 결과의 인용 문장을 해당 문서의 원문 줄과 대조했다.

## 발견한 문제 및 판단 보류
1. **질문 과다 가능성.** 짧은 오퍼 한 장의 생략이나 두 문서 모두 정보 부족만으로 5~7개의 질문이 생성된다. 규칙상 정상이라도 실제 사용자에게 질문의 우선순위가 모호할 수 있다.
2. **수습기간 분석 보류.** 오퍼 → 계약서 가상 시나리오에서 계약서 원문에는 수습기간 3개월이 있지만 수습기간 주제는 '분석 확인 불가'로 나왔다. 이로 인해 수습기간·수습 급여 두 질문이 하나로 묶이지 않았다. **원문 추출값·인용 검증/룰의 분기와 테스트 픽스처를 추가 조사해야 한다.** 이 QA 결과만으로 서비스 일반 오류 또는 AI 오류로 단정하지 않는다.
3. **결과 분류와 질문 사이의 맥락 부족.** 둘 다 적혀 있지 않은 주제마다 긴 질문이 생긴다. 결과 화면에서는 '핵심 차이'와 '선택적으로 물어볼 사항'을 구분하는 UX가 유용할 수 있다.

## 다음 결정 제안
현재 기획 기준(v2.2)에 맞는 분류 자체는 유지하고, 질문 목록을 **우선순위별 노출**할지 또는 **자동 생성 범위를 좁힐지** 제품 정책 결정을 먼저 한다. 임의로 변경하지 않는다.
