작성일: 2026-10-13 · 기준 브랜치: `claude/ildan-v31-qa-review` (`f856bfd`) · 상태: 구현 완료(로컬 커밋, 푸시·배포 전)
서비스 정의(유지): 입사 전, 확인해야 할 근로조건을 놓치지 않도록 돕는다 — 기록 · 확인 · 행동.
판정 범위(유지): 법률 위반·기업 신뢰도·조건의 유불리·회사의 의도는 판단하지 않는다.

## 1. 문서 유형별 역할

| 문서 | 단독 등록 시 화면 | 확인 질문 |
|---|---|---|
| 채용공고 | **저장된 채용조건**: 실제로 적힌 조건과 검증된 원문 근거만. 10개 기준의 미기재·불명확 표시 없음 | 만들지 않음(한 문서 안의 서로 다른 값만 예외) |
| 처우·근로조건 안내 (문자·메일 등, 선택) | **안내된 근로조건**: 적힌 조건만. 조건이 없으면 '근로조건이 발견되지 않았어요'(중립) | 만들지 않음(한 문서 안의 서로 다른 값만 예외) |
| 근로계약서 | **기재 상태 점검**: 10개 기준(동결 기준표 v2.2) 그대로 | 기존과 같음 |

- 협의 예정·추후 안내 예정 구분과 연봉 범위 처리는 그대로 쓴다(`f856bfd`).
- 채용공고·처우 안내도 서버에서는 기존과 같은 32개 세부기준 추출·원문 검증을 거친다. 화면 노출 방식만 바뀌며, 문서 간 비교에 필요한 값·근거는 계속 저장된다.

## 2. 문서 간 비교(유지)

- 조합 제한·순서 강제 없음: 공고↔계약서, 공고↔처우 안내, 처우 안내↔계약서, 3종 모두.
- 표시 구분: 서로 다르게 안내된 조건 / 새롭게 구체화된 조건 / 같은 내용 / 아직 확인이 필요한 조건 / 분석 확인 불가.

## 3. 저장과 분석의 분리

- 등록 순서: ① 원본 PDF 저장(있을 때) → ② 기록·확인 텍스트 저장 → ③ AI 분석 → ④ 분석 결과 저장.
- 분석에 실패해도 ①②는 유지하고 문서 상태를 '분석 실패'로 둔다. 같은 텍스트로 재분석할 수 있고, 재분석 때 원본을 다시 저장하지 않는다.
- 원본 저장에 실패하면 '원본 저장 실패'로 알리고(텍스트·분석은 계속), 기록 저장에 실패하면 지금처럼 '저장되지 않았어요'와 다시 저장.
- 문서 상태: `pending`(분석 전·중단) / `analyzed` / `analysis_failed`. 예전 기록(상태 없음)은 분석 결과가 있으면 `analyzed`로 본다.

## 4. PDF 원본 저장

- 저장 위치: 같은 IndexedDB(`ildan-hwagin`)에 `files` 저장소를 추가(DB 버전 1→2). 기존 `records`는 건드리지 않는다(삭제·초기화 없음).
- 저장 내용: 원본 Blob, 파일명, MIME 타입, 크기, SHA-256, 기록 ID, 문서 ID, 저장 시각. 문서에는 `original` 메타데이터만 둔다.
- PDF만 저장(형식·`%PDF-` 머리 확인). 이미지 원본은 이번 범위에서 저장하지 않는다.
- 같은 기록에 같은 파일(SHA-256 동일)을 다시 등록하면 새로 저장하지 않고 기존 원본을 연결한다.
- 기록 삭제 시 그 기록의 원본만 함께 삭제, 전체 삭제 시 모든 원본 삭제.
- 열람·다운로드는 저장된 Blob 그대로 사용한다(추출 텍스트로 재구성하지 않음).
- 서버에는 저장하지 않는다. 안내 문구: "파일은 현재 브라우저에 저장됩니다. 다른 기기에서는 확인할 수 없으며 브라우저 데이터 삭제 시 함께 사라질 수 있습니다."
- 예전 기록: 원본이 없으면 보기·다운로드 버튼을 보이지 않고, PDF로 등록했던 자료에는 '이전에 등록한 자료는 원본 파일이 보관되어 있지 않아요'를 안내한다.

## 5. 화면

- 기록 상단: 기록 이름 · 등록 자료 · **원본 PDF 보기/다운로드** · **새 안내 추가**.
- 채용공고·처우 안내만 있는 기록: '저장된 채용조건' / '안내된 근로조건'이 먼저, 등록 자료와 원문은 펼친 상태.
- 근로계약서가 있는 기록: 기존 '입사 전 확인할 내용 → 핵심 조건 요약 → 상세 확인' 유지.
- 문서 유형 이름: '오퍼·합격 안내' → '처우·근로조건 안내 (문자·메일 등)', 필수 단계가 아님을 표시.

## 6. 구현 메모

- 분석 중단(사용자가 분석 화면을 떠남)과 입력 형식 오류(400·413)는 등록 취소로 보고 방금 저장한 자료(와 다른 자료가 쓰지 않는 원본)를 되돌린다. 입력은 그대로 남는다.
- 저장소 쓰기 자체가 실패하면 예전처럼 '저장되지 않았어요'와 다시 저장(원본 포함). 저장과 분석이 모두 실패하면 오류 화면.
- 원본 보기·다운로드는 화면을 그릴 때 저장된 Blob으로 주소를 만들고 다시 그릴 때 해제한다. 원본을 찾지 못하면 버튼 대신 안내.
- 테스트: `test/v32-roles.test.js`(단위, 모의 AI), `scripts/e2e-originals.mjs`(브라우저, 데모 서버). 실제 Gemini로는 확인하지 않았다.
